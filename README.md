# 任务罗盘 · Agent Context Lab

**以用户目标为起点，复核 AI 任务的验收证据、执行过程与资源投入。**

大学生创新创业训练计划候选项目。当前 v0.16 提供网页评估、本机 Codex 执行连接、上下文与检索实验、证据补读、成本推演、长度对照、质量反例审计及停止前核验和对照实测。内置演示数据仍为人工构造；真实记录单独显示。尚无通用性能提升结论。

v0.10 整理工作台界面：任务概览优先显示当前数据集的任务、用量和验收分布；八个研究入口集中到“实验中心”，读取结果后进入策略比较。统一导航、表单、证据详情和停止前核验页，并支持窄屏布局。验收分布来自当前记录，示例状态明确标注。设计参考与检查范围见 [界面升级说明](ui-design.md)。

v0.11 新增原文片段 v2 开发预览：同预算切换整篇/片段选择，追踪原文位置、部分提交和省略范围；适配器默认在部分正文时停止，不消耗候选调用。66 项测试通过；六个已见任务的离线重放仍存在关键句遗漏，没有 v2 真实答案或用量结论。原 v1 冻结方法与实测保留，详见 [片段方法与开发重放](review-passages-method.md)。

v0.12 准备冻结后的新任务试点：六类新编题中预先选择两类，四种配置各重复两次，16 个配置格、最多 12 次调用。普通命令和网页检查不运行模型；真实启动须明确加 `--run`。双重哈希校验、模型可见引文评分、失败/未知费用停止、分重复结果页已实现，76 项测试通过。本轮没有新增真实调用，详见 [执行前计划](passage-study-plan.md)。

v0.13 完成 v2 新任务真实试点：16 个配置格、12 次调用、179,319 tokens。全读响应 4/4 通过；片段候选 2/4，导出边界句两次遗漏。默认停止 4 次未调用，但全部待核验；没有效率提升结论。原始记录经源码、输入、评分与用量审计，详见 [v2 试点实测报告](passage-study-report.md)。

v0.14 新增约束证据组 v3：将匹配句与边界、否定、适用范围、替代及数量线索整组选择；部分正文仍待核验，全文回退明确扩大预算。方法冻结后新编8类短/加长成对任务，四配置、四重复，固定256格，分批真实评估至额度或协议停止条件触发。每次调用存档并分批重算审计，未运行单列；过程记录见 [v3 实测检查点](bundle-study-report.md)，规则与限制见 [方法说明](review-bundles-method.md)、[执行前协议](bundle-study-plan.md)。90项软件测试通过，不代表模型准确率。

v0.15 新增资源决策工作台：按交付目标和正文预算比较停止、候选和全文提交，扩大预算需显式选择；决策依据在当前浏览器保存并导出。规划记录统一标记尚未执行，不伪造用量、完成率或人工耗时。v3 实验已在额度边界停止，39次调用中38次完成、1次失败且用量未知，已知580,180 tokens，217格未运行；最终报告与原始停止状态保留。详情见 [资源决策说明](resource-allocation.md)。

## 扩展后的课题定位

候选题目：**《面向用户目标的智能体任务评估与资源分配方法研究及平台开发》**。

AI 能搜索、编程、整理资料和处理数据；用户关心的是这些工作是否实现了自己的目标。平台将目标约定、执行记录、验收证据和资源成本关联起来，探索如何在保证目标完成质量的前提下分配资源。

软件成果是一套独立网页平台，接入不同 AI 工具的适配器可以是插件。代码修复仍是首个真实研究场景，资料研究和数据处理用于展示产品扩展能力，不意味着已经完成跨场景验证。

## 第一版已实现

- 三种场景、七条人工构造记录；任务搜索与场景筛选。
- 设置目标权重与必需项，查看基于验收状态计算的目标得分。
- 查看探索、执行、验证时间线，以及逐项目标的证据。
- 人工修正验收结论；判定通过或未通过时必须提供依据。
- 按同一任务、同一声明条件组比较记录，应用 token 预算。
- 排除验收失败、证据不完整、成本未知或超预算的记录；标记合格记录中 token 最少的结果。
- 下载 JSON 示例、导入自定义记录、导出当前任务评估报告。
- 手机与桌面布局；浏览器本地处理，无第三方页面脚本。

新增：调用本机已登录的 Codex，完成固定报名修复题；用 8 条独立测试验收，记录真实 token、耗时与最终修复选择，保存最近结果。

v0.3 新增：三种上下文各重复 3 次，固定模型请求名与推理强度，运行前保存协议，保留失败与未知成本；网页查看组内汇总、逐次证据和完整数据集导出。已完成 9 次真实调用，全部通过验收，详见 [预实验报告](context-study-report.md)。这只是一道受限题，不能推广成节省算力结论。

v0.4 新增：三种资料检索规则各运行 3 个配置恢复任务，加入一个目录标签错误的压力任务；网页可查看读取份数、通过率、逐任务证据和导出结果。已完成 9 次真实调用，详见 [资料检索对照报告](retrieval-study-report.md)。本轮发现标签覆盖不足以证明正文证据完整，不能把“少读文件”直接当成效率提升。

**尚未实现：**任意仓库修复、后台数据库、账户与协作、通用在线资源分配策略、通用隔离执行环境。

v0.5 增加受限的在线补读控制器：检查已读正文中的引用与数值，缺少依据时补读全部剩余资料，最多两次调用；标准答案只用于结束后验收。6 次策略运行共 7 次真实调用，补读修复了已知遗漏，但平均 token 更高。全部读取的一次失败来自来源编号格式，不能据此宣称新策略准确率更高。详见 [证据补读实验报告](evidence-study-report.md)。通用在线资源分配、语义证据核验与冲突检测仍未实现。

v0.7 增加长度与标签对照：同一题的每份正文扩展至 128 / 4096 字符，各设标签正确和错误两种条件，再比较两种策略。10 次真实调用完成 8 次策略运行，均通过；长资料标签正确时少用 8,413 tokens，错误且补读时多用 23,177 tokens。网页按条件展示结果；这不是自然遗漏概率或泛化验证。详见 [长度与标签报告](scaling-study-report.md)。

v0.8 增加无关真引文、隐藏冲突和资料缺失三类反例；区分正确恢复配置、按约定留空与误停。38 项自动测试通过；真实实验连续两次执行失败后停止，已知用量 29,482 tokens，未得到可用质量结论。详见 [质量审计与失败记录](quality-study-report.md)。

v0.8.1 修正事件流判定与中文分块解析，增加安全诊断；45 项自动测试通过。一次独立真实连接探测通过答案验收，用量 14,601 tokens。它没有重跑或改判旧质量实验，也不能证明策略更优。详见 [连接诊断记录](connection-diagnostics-report.md)。

2026-10-04 随后完成独立质量协议：6 次策略运行、8 次真实调用，合计 117,956 tokens。全读 3/3 满足响应约定，补读策略 2/3，隐藏冲突导致一次误停；补读策略总用量还高出 66.2%。三个人工反例不足以估计普遍错误率。详见 [质量反例实测报告](quality-results-report.md)。

v0.9 新增“打开停止前核验”：编辑资料、设定扫描与正文提交预算，查看词语匹配、不同数字线索和未覆盖文档。纯本地预览不调用模型；部分上下文只能生成待核验候选。51 项测试通过，尚未做新策略真实效果评估。方法与边界见 [停止前核验说明](review-method.md)。

v0.9.1 完成冻结后新编题的两题试点，四种配置共 8 次调用、118,159 tokens。全读和完整正文配置均自动完成 2/2；半量正文 0/2，两条错误候选均保持待核验；旧补读错误放行两条。本轮未证明性能提升。网页可读实测和导出 JSON，55 项测试通过。详见 [覆盖核验试点报告](review-study-report.md)。

v0.16 新增任务台账：关联固定决策快照，追加执行输出、失败尝试、未知用量与逐目标人工核验；新增执行不继承旧验收，部分正文候选不能直接算最终交付。执行与费用目前由人工填写，不调用模型；引文位置只作字面校验，人工验收不冒充独立验证。见 [台账说明](task-ledger-method.md)。

## 运行

v0.6 新增“打开成本推演”，比较一次全读与可能补读的期望 token，可填入上轮实测成本或手动调整假设；它不调用模型，也不预测质量。另有两个新编任务、5 次真实调用的迁移检查，运行前约束来源编号格式，两策略均通过，补读策略平均 token 高约 49.3%。详见 [成本推演与新任务报告](cost-validation-report.md)。

直接用浏览器打开 `index.html` 即可使用。也可以在 Node.js 20 或以上版本下运行：

```sh
npm start
```

然后打开 http://127.0.0.1:4173 。无需安装 npm 依赖。开发服务器只监听本机，使用固定文件白名单。

没有 npm 时也可直接运行 `node server.cjs`。真实运行需本机安装 Codex CLI 并完成 `codex login`；服务复用 CLI 登录，不读取或复制凭据，不需要把密钥填进页面。Windows 会检测桌面应用附带的 Codex；也可设置环境变量 `CODEX_BIN` 为可执行文件路径。仅直接打开 HTML 时，仍可使用离线评估，无法调用执行器。

点击“运行真实测试”，等待完成后查看验收证据；点击“查看最近结果”恢复本机上次记录。每次运行会使用 Codex 额度。也可运行 `node codex-bridge.cjs` 获取同一实验的 JSON 输出。

执行器用只读模式、临时目录、结构化答案和 3 分钟超时。仅允许预定义的修复选择进入可信测试函数，不执行模型生成的任意代码。模型默认值未固定，因此每次调用独立分组，不能用于策略优劣比较。详细边界见 [真实接入说明](live-experiment.md)。

## 验证

```sh
npm test
```

或 `node --test evaluation.test.cjs bridge.test.cjs context-study.test.cjs retrieval-study.test.cjs evidence-study.test.cjs cost-model.test.cjs scaling-study.test.cjs quality-study.test.cjs codex-response.test.cjs review-planner.test.cjs review-study.test.cjs review-passages.test.cjs passage-study.test.cjs review-bundles.test.cjs bundle-study.test.cjs resource-decision.test.cjs task-ledger.test.cjs`。测试本身不会调用模型。

覆盖核验试点：`node review-study.cjs` 或 `npm run review-study`。启动前校验冻结方法哈希，最多 10 次调用、160,000 已知累计 tokens 的调用间阈值，连续两次失败停止。六类题中仅预定前两类进入本试点；其他四类未运行。从“打开停止前核验”进入页面后点击“查看真实对照记录”只读取已有结果，不调用模型。

单次连接诊断：`node connection-probe.cjs` 或 `npm run probe`，每次仅调用一次模型并使用额度，不自动重试；输入、协议、源码和结果独立保存在 `runs/probe-*/`。它不属于质量策略对照。

上下文对照运行：`node context-study.cjs` 或 `npm run study`。最多 9 次；连续两次执行失败或已报告累计用量达到 180,000 tokens 后停止后续调用，不自动重试。停止阈值是调用间检查，非硬性计费上限。它不会修改原来的单次测试结果；完成后在网页点击“查看上下文对照”。

资料检索对照运行：`node retrieval-study.cjs` 或 `npm run retrieval`。同样最多 9 次，保存每次选择的资料、停止原因、配置答案和独立核验结果；完成后在网页点击“查看检索与停止实验”。这项实验的检索是平台规则，不是模型自主搜索。

证据补读运行：`node evidence-study.cjs` 或 `npm run evidence`。3 任务 × 2 策略，最多 9 次模型调用；两轮用量累加，部分用量缺失时总成本仍为未知。网页点击“查看证据补读实验”，可逐轮复核所读资料、token 和停止原因。旧实验结果保留在各自文件中。

新任务检查：`node validation-study.cjs` 或 `npm run validation`，最多 6 次模型调用、120,000 已知累计 tokens 的调用间阈值；完成后点击“查看新任务检查”。使用预先限制的来源 ID，旧实验默认格式与原始评分保留。

测试覆盖质量门槛、缺失证据、缺失成本、预算限制、条件组隔离、无效导入和并列结果。浏览器还应检查导入、预算交互、人工复核与报告导出。

长度与标签对照：`node scaling-study.cjs` 或 `npm run scaling`；最多 12 次调用、260,000 已知累计 tokens 的调用间阈值，连续两次执行失败停止。生成的完整资料、条件和源码哈希在调用前保存。网页点击“查看长度与标签对照”；结果独立保存，不覆盖旧实验。

质量反例运行：`node quality-study.cjs` 或 `npm run quality`；最多 9 次调用、150,000 已知累计 tokens 的调用间阈值，连续两次执行失败停止。页面点击“查看质量反例审计”。本组通过率包含按约定留空，不能当作配置恢复率；最近协议已完成，旧提前停止的协议独立保留。

## 使用和数据边界

从任务卡片进入策略比较，调整目标和预算，点击“应用预算”；进入记录详情查看或修正验收证据；导出评估报告保存当前任务和复核结果。更改条件仅重评已有记录，不会重新运行 AI。

页面复核修改仅保存在内存中，刷新会丢失；原始真实结果保存在本机 `runs/`，可用“查看最近结果”恢复。该目录已忽略，不上传仓库。平台不会自行证明导入记录真实，也不会执行日志中的代码或指令。导入说明见 [数据格式](data-format.md)。

成本未知不等于零成本；token 不等同于硬件算力；重复操作不自动等于浪费；单次优胜不等于策略普遍更好。
